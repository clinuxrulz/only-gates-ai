Integer GPT · field notes

A GPT that runs on integers — and is being lowered to gates.

Training still needs floating point and gradients. Inference does not. This project keeps the model's arithmetic in int8 and Q16, turns the forward pass into a fixed integer dataflow, and is working toward the step after that: pure logic gates on an FPGA.

The one-minute version

Three facts explain the whole idea

01

Training is float

Gradients, AdamW moments, and loss need fractional values and dynamic range. A GPU does this part. The output is a checkpoint: a few million ordinary numbers.

02

Inference is fixed arithmetic

Once the weights stop changing, the same matrix products, norms, exponentials, and comparisons run for every token. That is compatible with int8 storage, Q16 scaling, and integer accumulation.

03

Gates are the next rung

Integer adds, compares, shifts, and table lookups are made of logic gates. Lower the graph far enough and it can become an FPGA bitstream instead of a program.

What is inside

A decoder-only transformer, small enough to inspect

The browser demo and the community training target are the same architecture at two sizes. Tokens become learned embeddings, pass through pre-norm transformer blocks, and are projected back onto the vocabulary with the same embedding matrix. There are no biases, no learned position table beyond a small embedding, and no exotic operators: every operation has an integer implementation.

Why integers

Small values, wide accumulators, no floating point

Quantization is not “round everything to whole numbers and hope.” The model keeps a scale beside each group of weights and each activation row. A value is stored as an int8 code and interpreted as code × scale. Products are accumulated in int32 because int8 × int8 fits comfortably; anything that multiplies a scaled value again moves to int64. Probabilities live in Q15, where 32768 means one.

What the integer path buys

  • Roughly 4× smaller weights than float32, plus one small scale per channel.
  • Deterministic arithmetic: the same bytes produce the same logits.
  • No FPU, no denormals, no NaN policy differences between devices.
  • Cache-friendly rows that map directly to adders and multipliers.

What it costs

  • Outputs differ from the float checkpoint; top-1 usually survives, exact text does not.
  • Scales are chosen at load time, so a different checkpoint needs a fresh conversion.
  • Very large activations need clipping and careful Q-format choices.
  • Training cannot run on the integer path; gradients still need float.

The integer toolbox

Every operator has a fixed-point version

RMSNorm without a square root instruction

Sum the squares, divide by the width, take an integer square root, then multiply by a Q16 reciprocal.

sum = Σ x[i] * x[i]
mean = sum / dim
inv = (1 << 16) / isqrt(mean)
y[i] = (x[i] * inv * gain[i]) >> 16

GELU as a lookup table

The tanh approximation is smooth and bounded. A small Q12 table plus linear interpolation replaces the transcendental call.

index = clamp(x, -4, 4) mapped to Q12
y = lut[index] + slope * fraction
// one table shared by every MLP row

Softmax with DI-Exp

Subtract the maximum logit, clip the negative difference, and look up exp(-x) in Q15. Normalize with a rounded integer division.

delta = max_logit - logit
p = exp_neg_q15_q12(min(delta, CLIP))
p = p * 32768 / Σp

Attention with per-row scales

Q, K, and V are quantized per position. Scores accumulate in int64, softmax produces Q15 weights, and the value sum is requantized once.

score = Σ q8[d] * k8[d] * q_scale * k_scale
weight = softmax_q15(scores)
out[d] = Σ weight[j] * v8[j][d] * v_scale[j]

Sampling with xorshift

Top-k keeps the candidate set small. A 32-bit xorshift generator supplies deterministic randomness without a platform RNG.

x ^= x << 13; x ^= x >> 17; x ^= x << 5;
pick = x % total_weight
// walk the Q15 candidates

The rule that keeps it honest

Floating point is allowed in exactly one file: the load-time quantizer. The inference translation unit contains no float type, literal, or math library call.

tiny_gpt_quantize.c  // float allowed, once
tiny_gpt_infer.c     // integers only
int_math.h           // Q16 / Q15 / Q12 helpers

Float to integer

Five steps from a checkpoint to a token

  1. Train in float. Backpropagation and AdamW need fractional state. This is the expensive part and the part that needs community compute.
  2. Export the checkpoint. The trainer writes weights.bin, tokenizer.json, and checkpoint.json in the exact packing order the C loader expects.
  3. Quantize at load. Per-channel scales turn weights into int8. Activations are quantized per row to int8 with a Q16 scale. This is the only place float appears.
  4. Run the integer forward pass. Embeddings, RMSNorm, attention, MLP, final norm, and softmax all stay in integers.
  5. Compare against float. Measure top-1 agreement, top-5 overlap, and mean probability delta. Preserve the behavior that matters; do not claim identical text.
Resumable by design. The community trainer checkpoints the model, AdamW moments, scheduler, RNG, and QA cursor to latest.pt. A free Colab session can stop at a time budget and the next session continues from the same optimizer step.

Integers to gates

Arithmetic is a circuit waiting to be written down

An integer operation is not magic. An 8-bit adder is a handful of gates. A comparator is a tree of them. A shift by a constant is wiring. A multiply by a constant can become a shift-add network or a small ROM. A lookup table is a decoder plus a mux. The quantized model is already a fixed dataflow, so the lowering problem is “schedule this graph onto gates and memory,” not “invent a new model.”

What the gate compiler already does

The repository's compiler takes a trained hard-mode gate forest, builds a boolean AST, simplifies it with constant folding, identity, absorption, De Morgan, and common-subexpression elimination, then emits pure bitwise code. That proves the lowering pipeline on small symbol-classifier circuits.

What a GPT still needs

Wider arithmetic lowering, a schedule for matrix tiles, on-chip memory planning, control for token-by-token decoding, and a verification path against the integer reference. Those are the open engineering problems, not reasons the idea fails.

Why an FPGA

Fast, offline, deterministic, and low power

An FPGA is a grid of lookup tables, flip-flops, block RAM, and DSP slices that can be wired into a custom machine. It is not as fast as a GPU at training, but inference is not training: it is a fixed pipeline that can be deep, wide, and local. A gate-lowered GPT could answer without an operating system, a driver, a network, or a floating-point unit.

Benefits worth chasing

  • Deterministic latency: a fixed pipeline, not a scheduler.
  • Low power: no CUDA stack and no wasted floating-point work.
  • Offline and private: the model and the prompt stay on the device.
  • Deep pipelining: every layer can work on a different token at once.
  • Long life: a bitstream can run unchanged for years.

Trade-offs to state plainly

  • The model is fixed at synthesis time; changing weights means resynthesis.
  • On-chip memory is limited; larger models need external DRAM.
  • The clock is far below a GPU; a tiny model fits, a large one does not.
  • Quantization changes outputs; verification is part of the work.
  • RTL, timing closure, and board bring-up are substantial engineering.
What success looks like: a gate-lowered transformer block that matches the integer reference bit for bit in simulation, then one measured board report with clock, tokens per second, latency, LUT/FF/ BRAM/DSP use, and power. Publish the numbers even if they are modest.

Questions

Answers before you ask

Do I need a GPU to help?

No. The smoke test and the float-vs-integer evaluation run on a CPU. Real training runs are much faster on a free Colab T4, but code, evaluation, documentation, and RTL review need no GPU.

Is integer inference bit-identical to the float model?

No. Quantization changes the numbers. The goal is to stay close enough that the top prediction and the character of the output are preserved. The app ships a float-vs-int8 comparison so the difference is visible rather than hidden.

Is the whole GPT running on an FPGA today?

Not yet. Integer-only inference in WebAssembly is working. The gate compiler is a prototype for small symbol-classifier circuits. Lowering a full transformer to gates and running it on an FPGA is the roadmap, not a finished feature.

What does resume actually restore?

The model weights, AdamW optimizer moments, learning-rate scheduler position, Python/NumPy/PyTorch RNG state, the LM step, the QA epoch and batch cursor, and the exact QA example permutation. A resumed run continues from the same place instead of restarting.

Why not just use an existing CPU inference engine?

Speed alone is not the point. The project wants a model whose inference is a fixed integer dataflow that can be lowered to logic gates and mapped to an FPGA. That constrains the operators, the precision, and the memory layout from the start.

Can I use a free Colab account?

Yes, within Colab's terms. Free sessions are time-limited and can disconnect, which is why the trainer checkpoints to Google Drive and resumes. Start with the smoke test, keep one account, and do not try to work around usage limits.

How is contributed work credited?

Compute runs report the checkpoint hash, configuration, seed, hardware, and wall time in a GitHub issue. Results used in a release are listed with the contributor and the run. The repository is MIT licensed; upstream corpora keep their own licenses.
